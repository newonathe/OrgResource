# Superpowers planning for OrgResource

1. Read the governing repository and course sources. Resolve the exact worktree, base SHA, current phase, and approved product scope before proposing changes.
2. Compare existing behavior with the requested outcome. Resolve routine decisions from source. Ask only when a material ambiguity blocks safe implementation or changes the authorized scope.
3. For consequential work, record the smallest coherent change with affected paths, dependencies, observables, denial cases and acceptance commands. Match plan detail to risk. Use a brief checklist for a well-defined correction.
4. Once scope is clear, proceed through the implementation skill and track the first incomplete check so a resumed session can pick up from actual evidence.
