## Preferred engineering route
Separate feature/draft verification-only adapter; keep existing Linux harness and protected source unchanged. Use native PowerShell 7.4+, Java21, MySQL8.0.46 Windows, Python and CLI Playwright. Prefer an isolated Windows Sandbox session with networking disabled if supported, enabled with approval, sufficient memory/disk, actual localhost TCP/MySQL/browser verified, and all required tools cached/staged from authorized sources. Microsoft Learn https://learn.microsoft.com/en-us/windows/security/threat-protection/windows-sandbox/windows-sandbox-overview and https://learn.microsoft.com/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file document supported editions and read-only mapped folders/network disable. Sandbox is optional and may require admin/restart; do not assume it is installed or supported. No private plan or JAR mapping without specific custody authorization. Narrow read-only input map, separate private output custody, no whole home directory; no clipboard or unrelated device mapping. Prove network disabled, loopback works, no route to host/network, no public upload, clean isolated environment. Test all controls with fictional data first. If Sandbox unavailable, native host isolation requires a reviewed fail-closed outbound restriction for all children (not just bind-address or application flags), exact Windows process handles/Job Objects and ACLs. Microsoft https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects documents process tree kill-on-job-close; it does not establish network isolation. No automatic firewall rule changes or broad privileges. If equivalence cannot be demonstrated, refuse private run. Existing approved offline Linux VM on Windows is a possible alternative without WSL, subject to same local private and owner controls; no new VM/paid resource by default.
