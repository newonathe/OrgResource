### Relational DB, ARM packages, transaction guarantee
[MySQL 8.4 official InnoDB locking-read doc](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html): `SELECT ... FOR UPDATE` must occur **inside transaction**, locks rows until commit/rollback; ordinary reads alone cannot safely serialize a reservation. Backend must use transaction lock ordering, idempotency/operation uniqueness, composite tenant FK and rollback. [MySQL 8.4 downloads](https://dev.mysql.com/downloads/mysql/8.4.html) show 8.4 LTS line; exact **2026 ARM64 Linux 8.4 server package/OS compatibility not proven on chosen OCI image**. [MySQL Linux install](https://dev.mysql.com/doc/refman/8.4/en/linux-installation.html) details package choices but generic Linux instructions do not equal successful ARM64 deployment.

**Alternative:** [PostgreSQL official Ubuntu arm64 packages](https://www.postgresql.org/download/linux/ubuntu/) explicitly list arm64 for LTS Ubuntu; supported relational/JPA option if MySQL ARM package or compatibility fails. But this changes SQL dialect, migrations, lock behavior and course V1 DB; use only as **separate production V2** and re-test constraints, row locks, intervals and restore. PostgreSQL is not a silent original-course/MySQL replacement. **Early DB/OS matrix and reproducible real `FOR UPDATE` 100-concurrency test required for choosing DB**.

### Newly verified viable direction: HTTPS without buying a domain
**Official fact:** [Let's Encrypt 2026-01-15 GA announcement](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability) confirms **IP-address TLS certificates** generally available, validity **160 hours**, approximately 6 days 16 hours. [Certbot 2026-03-11 guide](https://letsencrypt.org/2026/03/11/shorter-certs-certbot) describes Certbot **5.3+** IP flag and **5.4+ for webroot**; HTTP-01 [challenge guide](https://letsencrypt.org/docs/challenge-types/) requires external port **80** reachable for validation. This may eliminate a custom paid hostname: use an assigned **stable public IPv4** and automated short-lived certificate renewal with a carefully configured reverse proxy for a public `https://IP/` URL.

**NOT PROVEN:** OCI free eligible stable public IP and charging terms; an IP allocation supported by the exact account; issuance and browser trust of certificate for exact IP; dual-stack limitations; renewal at least every 1–2 days, alarm/recovery if renewal fails; valid reverse-proxy reload, external TLS scan and 401/403/CSP/cookie testing under IP origin; redirect HTTP to HTTPS while still serving ACME; host firewall and private DB. A raw-IP URL is less usable for nontechnical people but can technically carry a valid cert if verified. **160-hour cert + host outage/reclaim is material availability risk**, not automatic “free TLS solved.” [OCI public-IP docs](https://docs.oracle.com/en-us/iaas/Content/Network/Tasks/managingpublicIPs.htm) distinguish ephemeral and reserved IPs, but do not establish zero-charge for every reservation/assignment in this account. Alternative free subdomain must be separately verified for provider terms, free availability, issuance and control; do not invent.

### Storage/backup failure domains
OCI offers object storage within account, not automatically an **independent account failure domain**. VM disk/OCI volume snapshot and OCI object in same tenancy may fail together on account loss/reclaim/restriction. **Design recommendation:** encrypted SQL/database export with schema/version/event checkpoint and checksums to OCI free object tier **plus** user-held offline encrypted copy or **independently authorized and metered** separate provider; key stored separately. [Cloudflare R2 pricing](https://developers.cloudflare.com/r2/pricing/) offers 10GB-month Standard, 1m writes, 10m reads free, but [R2 start](https://developers.cloudflare.com/r2/get-started/) explicitly requires an R2 **subscription checkout** and usage beyond allowance is billed; [billing profile](https://developers.cloudflare.com/billing/get-started/create-billing-profile/) may require payment method. **Do not call R2 an automatically zero-billing second backup destination** absent cap/control and account evidence. An owner-owned local offline copy costs no *provider subscription* but requires operational time, actual separate location/custody, manual schedule and clean restore test. Encrypt before upload; no real credentials/test user data in Git. If **backup outside primary account with reliable copy cadence or restoration** cannot be demonstrated, P-ACCEPT BLOCKED.

## 4. Identity/session architecture and permission boundaries
**RECOMMENDATION:** If an institutional OIDC and free reliable email/reset service are unverified, V2 may begin as **invitation-only local identity** for *fictional* testers, with centrally controlled creator/invite/recovery, no real campus org self-claim. Use Spring Security and its [delegating password encoding](https://docs.spring.io/spring-security/reference/features/authentication/password-storage.html) with current adaptive hash and calibrated cost; verified unique subject; secure rotation and revocation; limited password attempts/rate limits; no email-only role assignment. Real human account availability/notification/recovery remains a **separate consent/privacy and operations gate**, not a claim of pilot adoption.

**Session/cookie gates:** [OWASP session guidance](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) requires Secure+HttpOnly and SameSite as defense in depth; prefer host-only session cookie, HTTPS-only, not exposed JavaScript credential. [Spring Security CSRF](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html) requires CSRF tokens for cookie-authenticated unsafe actions; React SPA needs token refresh on login/logout. `SameSite` alone isn't a substitute. Validate session fixation rotation, logout/revocation, disable/remove membership immediately, privilege escalation, invite replay/expiration, last-owner recovery, 2-tenant IDOR/BOLA on **every** resource/export/audit route. Demo public mode should be anonymous **read-only** or per-visitor isolated/reset sandbox with no real outbound emails/SMS, synthetic people/assets and no "official Ateneo" claim.

**Special Jersey/Spring filter caveat:** [Boot Jersey security how-to](https://docs.spring.io/spring-boot/how-to/jersey.html): configure `jersey.config.server.response.setStatusOverSendError=true` for method security to yield correct authorization failures. Security filter-chain coverage must be demonstrated against real Jersey paths, not only MVC tests. Dedicated operator cannot read tenant content automatically.
