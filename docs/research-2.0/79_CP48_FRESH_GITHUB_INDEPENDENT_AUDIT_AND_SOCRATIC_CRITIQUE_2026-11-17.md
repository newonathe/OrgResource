## 4. Socratic interrogation protocol — apply to EVERY relevant source file and EACH changed logical block

Codex auditor must write an audit row **per file**; for every changed method/route/query, include **line range** and answer these nine questions using real evidence:

1. **Authority:** Which exact assignment/syllabus paragraph, original project proposal, current code contract, or explicit user C decision authorizes this line? If none, why add it?
2. **Meaning:** What happens to the same user's request before and after this code? Is a historically recorded behavior being changed?
3. **Boundary:** Who can call it? Which active organization/role owns every referenced row, image, retry receipt, response or background job?
4. **Integrity:** What invariant must always be true? Could a concurrent request, wrong clock, null, overflow, deleted parent or replay violate it?
5. **Counterexample:** Construct at least one specific invalid request/state/SQL row that would cause incorrect behavior if this logic were wrong.
6. **Observation:** Which *executed* test, HTTP request, SQL postcondition and SHA proves the behavior? If only code/report text, mark SOURCE_ONLY or REPORTED_PASS.
7. **Failure:** If the provider times out, DB rolls back, browser refreshes, SMTP/SMS/host fails, or image invalid, does the app falsely claim success or leak data?
8. **Preservation:** Does this touch source/behavior frozen in A? If yes, why is a C adapter not enough, and was the diff approved and A/B regression run?
9. **Cost/scope:** Can this incur paid service, log secrets/personal data, bloat the deliverable or delay December5? If yes, is there an explicit authorization and contingency?

**Scoring:** `P0` means course release/security/stock correctness or source-lineage blocker; `P1` important before public B acceptance; `P2` documentation/clarity/technical debt. Each file's results must be tagged `PASS/FAIL/PARTIAL/BLOCKED/NOT_RUN`, and uninspected code must not be marked PASS.
