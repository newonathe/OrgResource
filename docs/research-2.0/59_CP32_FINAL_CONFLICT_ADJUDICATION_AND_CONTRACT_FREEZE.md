## C. Canonical P0 domain semantics — calculations, transitions and guardrails

**Times:** All comparisons use one injected `Clock` sample per operation in UTC. Project `startAt<endAt` and creation `startAt>now` remain source-aligned. `timePhase` is UPCOMING if `now<startAt`, IN_PROGRESS if `startAt<=now<endAt`, ENDED otherwise. `APPROVE` checks **not ended**, not IN_PROGRESS. `ISSUE/CONSUME` require IN_PROGRESS. An `ISSUED` reusable allocation can be returned after project end. No future-window resource reuse optimization.

**Resource state:** `kind=REUSABLE|CONSUMABLE`, `T=total_quantity`, `H=sum APPROVED(q) whose project endAt>now`, `I=sum ISSUED(q) on REUSABLE`.
- REUSABLE: `available=T-H-I`; quantity is physically owned total, including items currently borrowed.
- CONSUMABLE: `available=T-H`; on CONSUMED, `T := T-q`.
- Requirement `covered=sum(q for ISSUED|RETURNED|CONSUMED) + sum(q for effective APPROVED)`, `shortage=max(0, requirement.quantity-covered)`. **PENDING never holds stock.**
- Conserve `0<=H,I,T<=1,000,000` and available≥0. Use checked 64-bit intermediate sums. No stored `available` writable field. Two concurrent q4 approvals of reusable T5: exactly one may commit, second 409. Requester permissions and same-org FKs must be checked in same transaction.

**Allocation status transitions:** `PENDING -> APPROVED` if demand/stock sufficient and not ended; `APPROVED -> ISSUED` reusable in interval; `ISSUED -> RETURNED` reusable whole usable q (even after end); `APPROVED -> CONSUMED` consumable in interval, deduct q once; `PENDING|APPROVED -> CANCELLED` on user cancel or scheduler after end. There is **no** `EXPIRED` allocation status, only `CANCELLED` with reason `EXPIRED`. `approvedAt` remains historical. No transition from RETURNED/CONSUMED to APPROVED. Expired-but-not-cleaned APPROVED is visible with `expiredPendingCleanup=true, isEffectiveHold=false`. Scheduler never auto-returns custody and never generates stock movement for reservation release.

**Stock movement ledger:** `INITIAL +q`, `RECEIPT +q`, `ADJUST (newT-oldT)`, `CONSUME -q` affect total; `ISSUE +q`, `RETURN -q` affect issued outstanding (not total). Immutability plus `UNIQUE(org_id,operation_id)`, action/payload fingerprint and transactionally recorded actor. A zero-delta R03 rename is *not* a stock movement; a public explicit ADJUST with same total is 422 `NO_STOCK_CHANGE` rather than a false history event. Every attempt that changes T/I must have stable operation identity, and a replay after 48h/restart must not apply again. HTTP 24h idempotency receipts are separate, shorter-lived optimization. Domain receipt replay: authorize current principal first, check stable operation+payload; same => return canonical result, different payload =>409, no second movement. Race on unique key must use DB conflict control, not application-only existence checks.

**Critical stock error labels:** `INSUFFICIENT_STOCK` when q>available; `REQUIREMENT_ALREADY_COVERED` for exhausted requirement; `OUTSIDE_PROJECT_PERIOD` for ISSUE/CONSUME outside interval; `PROJECT_ENDED` for APPROVE/CREATE after end; `INVALID_ALLOCATION_STATE` for wrong transition; `QUANTITY_BELOW_COMMITMENTS` for unsafe T/Q decrease; `HISTORY_PROTECTED` for disallowed delete. Original /api preserves its observed messages where applicable; public v2 codes can be mapped with an explicit compatibility table.

## D. Canonical v2 HTTP/security contract for implementation drafting

**Base:** `/api/v2`. Org domain paths: `/api/v2/orgs/{orgId}`. Every nonpublic business action checks current authenticated account ACTIVE, org ACTIVE, active membership+role, resource/project ownership and optionally activeOrgId. The public `orgId` UUID identifies a target, **never** grants access. Foreign tenant IDs answer 404 without revealing metadata; wrong role on visible object 403; anonymous 401.

**Origin/session/CSRF:**
- `GET /api/v2/auth/csrf` creates limited pre-auth session+csrf token, returns `{data:{csrfToken},requestId}`, `Cache-Control:no-store`.
- `POST /api/v2/auth/login` with username/password, pre-auth cookie and `X-CSRF-Token`; generic 401, throttled 429; success rotates session and CSRF; cookie `HttpOnly;Secure;SameSite=Lax` over trusted HTTPS (local test permitted isolated http without production exposure).
- `POST /api/v2/auth/logout`, `POST /api/v2/auth/recover` and `POST /api/v2/invitations/redeem` require valid CSRF and same-origin protection. Password recovery uses stored one-time *hashed* code and rotates credential_version/invalidate all sessions; never auto-activates disabled account.
- `GET /api/v2/session`, `GET /api/v2/orgs`, `POST /api/v2/session/active-org` set/revalidate org context; active-org switch never grants roles and rotates/revalidates auth context. No implicit default first org. Protected /api uses only session-selected validated org.
- `POST /api/v2/invitations/redeem`: (i) no account: `{token,username,newPassword}` creates LOCAL account and membership atomically; (ii) already authenticated: `{token}` adds membership atomically. Both: token >=128 bits, hash stored, status INVITED, not expired, target role excluding OWNER, org ACTIVE, no duplicate membership, single winner on races. Credential and token never appear in URL or logs. This is **fictional invite possession**, not verified personal or Ateneo identity. Return 201 for new account, 200 for existing, with a new secure session where applicable.
- `POST /api/v2/orgs/{orgId}/invitations`: OWNER may invite ADMIN/CUSTODIAN/LEAD/MEMBER; ADMIN only CUSTODIAN/LEAD/MEMBER; neither can invite OWNER. Initial first OWNER is offline operator-provisioned via a one-time local bootstrap command, no Internet self-claim, no permanent operator backdoor. Ownership transfer only CURRENT OWNER -> ACTIVE ADMIN accepting, atomic swap and last-owner preservation.

**Public success:** `{ "data": <typed DTO>, "requestId": "req_<opaque>" }` and optional `"page":{"nextCursor":null|"opaque","limit":20}` for lists. Public error: `{"code":"...","message":"...","requestId":"req_<opaque>","details":{...}}`. Fixed 400 parse/format, 401 anonymous, 403 wrong role/CSRF, 404 hidden or absent, 409 domain/duplicate, 412 stale ETag, 422 semantic validation, 428 missing If-Match, 429 throttled, 503 temporary dependency, sanitized 500. Exact controller-level messages for original protected /api stay unchanged except clearly documented auth/context extension.

**Concurrency/preconditions:** all public *domain* POST mutations require 128-bit `Idempotency-Key` and valid CSRF. Creates do not need If-Match; update/transition/delete require `If-Match: "<integer version>"`, respond 428 if absent/412 if stale. Auth endpoints use CSRF/rate limiting but not the domain receipt scheme. Physical stock actions additionally require stable UUID `operationId`. If an authenticated same-key/same-payload replay arrives before a later version check, return the original committed receipt, not a misleading new 412; if key and new body differ, 409. Never omit current membership authorization on replay. Return latest `ETag` after committed mutation.

## E. Physical database contract changes to CP31's 18-table candidate

**Candidate count:** `organization,user_account,local_credential,account_recovery_code,membership,invitation,ownership_transfer,department,project,resource,requirement,allocation,stock_movement,audit_event,idempotency_key,SPRING_SESSION,SPRING_SESSION_ATTRIBUTES,resource_image` = **18** (depends on selected identity framework and session-storage schema). It is NOT existing DDL. Original five semantic JPA entities must remain genuinely present.

- **Required keys:** primary BIGINT IDs, public lower-case UUID `CHAR(36)` unique with binary collation, tenant `org_id`, mutable `version BIGINT`, lifecycle timestamps as UTC `DATETIME(6)`. Confirm actual MySQL collations, generated SQL, ownership and lock order through tests.
- **Project:** `org_id, department_id, lead_membership_id?, name, start_at, end_at, version`; NO stored status in P0. `end_at > start_at` SQL CHECK plus service rule future start on create. Public read derives `timePhase`. Same-org composite FKs to Department and (optional) lead Membership.
- **Account:** `user_account` MUST include unique normalized login `username_key` and display username, status ACTIVE/DISABLED, credential_version; `local_credential` holds password hash. Prior candidate `auth_subject` may act as username key, but a concrete username-to-account lookup is mandatory for login/recovery/anonymous invitation redemption. Auth recovery codes hash+used/revoked timestamps.
- **Membership:** `UNIQUE(org_id,user_id)`, effective ACTIVE OWNER requires ACTIVE account+membership+organization. All owner-impacting operations serialize org-root first; global disable locks all relevant org roots ascending and revalidates effective owners before commit. Password reset holds account locks and never later acquires org root in that transaction.
- **Allocation:** include `borrower_name_snapshot` required and `borrower_membership_id` nullable for real original A01; `requester_membership_id` required on secured new inserts, nullable only for migration provenance with strict gating. Include all O14 status/history fields and separate encrypted optional notification destination+consent/outcome/claim time. Parent matching `(org_id,requirement_id,resource_id)` to `requirement(org_id,id,resource_id)`; all non-null tenant-sensitive FKs explicit.
- **Stock movement:** `UNIQUE(org_id,operation_public_id)`; resource same-org FK; ISSUE/RETURN/CONSUME require allocation_id and matching resource triple FK; INITIAL/RECEIPT/ADJUST allocation nullable; kind-specific signed deltas and amounts checked. No `ON DELETE CASCADE` history; `T = SUM(delta_total)`, `I = SUM(delta_issued)` reconciliation.
- **Resource:** `name_key` unique per tenant, kind immutable after any allocation or movement, `total_quantity` matches movements. Resource may be zero-deleted if NEVER moved or referenced and has no dependent image. To avoid contradiction, **do not create a zero INITIAL movement**.
- **Resource image:** at most one Resource image, `UNIQUE(org_id,resource_id)`; <=2 MiB actual decoded JPEG/PNG/WebP only, safe content sniffing/dimension cap; authenticated POST upload and GET bytes; origin traversal/SSRF disallowed. Course CLO9 interpretation still Canvas-owned.
- **Identity/session and migrations:** Spring Session two tables are framework/version-dependent; load schema from the exact selected library. Run versioned migrations (Flyway/Liquibase choice after dependency and licensing check), prohibit `ddl-auto=update` in public environment, test migrations from empty DB and preexisting O14 data.
- **MySQL CHECK cannot guarantee cross-row global stock or >=1 effective owner**. Lock, check and write in one transaction; direct SQL FK and 100-way race tests required. No `MATCH` clause in FK declarations. Never use mutable HTTP receipt as sole physical stock dedupe.
