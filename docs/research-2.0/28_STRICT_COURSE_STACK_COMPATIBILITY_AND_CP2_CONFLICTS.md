## MC-01 — javax.validation is a material public-runtime compatibility conflict
[Jakarta Validation 3.1 specification section 2.2](https://jakarta.ee/specifications/bean-validation/3.1/jakarta-validation-spec-3.1.html) explicitly moved javax.validation to jakarta.validation as of specification 3.0. [Hibernate Validator 6.2](https://hibernate.org/validator/releases/6.2/) retains javax and identifies **limited support** and declared Java8/11/17 compatibility. New Hibernate Validator 9.x uses jakarta.validation. [Spring Boot 3 migration](https://github.com/spring-projects/spring-boot/wiki/Spring-Boot-3.0-Migration-Guide) moves to Jakarta Servlet/JPA; [Boot4.1.2 BOM](https://docs.spring.io/spring-boot/appendix/dependency-versions/coordinates.html) manages Jersey4.0.3, which uses Jakarta REST. Therefore Boot4/Jersey4 is not a drop-in execution of the original javax-validation annotations; annotation classes have different fully qualified names. Adding both validator versions in one Maven dependency graph is not an established solution; explicit isolated provider/bootstrap and classloader compatibility proof is necessary. No fully supported, no-mandatory-fee, single public process preserving every literal javax path was verified.
Jersey **2.48** service release on **2026-03-18** still implements legacy Java EE8/JAX-RS2.1, per [Eclipse release](https://projects.eclipse.org/projects/ee4j.jersey/releases/2.48). This does not bring Spring Boot2.x/Spring Framework5 into supported OSS status: [Boot2 OSS ended 2023-11-23](https://spring.io/blog/2023/11/23/spring-boot-2-7-18-available-now/); [Framework5.3 OSS ended 2024-08-31](https://spring.io/blog/2024/03/01/support-timeline-announcement-for-spring-framework-6-0-x-and-5-3-x/). **Do not internet-expose the O14 legacy runtime merely because Jersey2 received later fixes.**
