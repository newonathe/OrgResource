# V2 nonfunctional requirements (NFR) and bounded workload
**Status:** PROVISIONAL RECOMMENDATION — numerical targets are **design targets, not measurements, service guarantees, or provider quotas**. **Date:** 2026-11-15. E02–E18, G06–G10.

## Explicit synthetic capacity envelope, not observed Ateneo use
Initial sizing **assumption**: 50 fictional workspaces, 20 memberships/workspace (1,000 memberships), 200 resources/workspace (10,000 resources), 40 active projects/workspace, 8 requirements/project, 4 allocations/requirement worst (64,000 allocations over synthetic 50×40×8×4), ~0.5 million append-only events over cumulative history, 25 peak concurrently active requests in simulation. This is a load model, not enrollment, stock or actual demand. Limit growth with tier-aware retention, keyset pagination, export then archive, no hard deletion of unexpired legal records. Physical data size must be measured with EXPLAIN/dumps before hosting.

### Performance/storage estimation method (not a measurement)
For each table compute `avgBytesPerRow = measured table bytes / rows` on engine chosen; total storage budget = tables+indexes+event growth+backups/temp+provider headroom. At an illustrative 500,000 event rows × assumed 250 bytes ≈ 125MB **before indexes, blobs, snapshots and overhead**; cannot claim this passes a 500MB D1 limit without measuring actual schema/indices and historical growth. Under D1, 50 page requests/s each with table scans could exhaust 5m rows/day rapidly. Add composite indexes and cap list page size. If targets exceed free budget, **reduce admitted workspace/storage/load envelope or defer deployment**, not silently pay.

### Quality go/no-go
No public multiuser hosting until N01/N04/N07/N08/N11/N14 proven, critical dependency vulnerabilities resolved, actual provider eligibility and $0 ledger verified, and consent/privacy text reviewed. If free-term/provisioning prevents N02/N05, retain local-only functional demo rather than assert permanent availability.
