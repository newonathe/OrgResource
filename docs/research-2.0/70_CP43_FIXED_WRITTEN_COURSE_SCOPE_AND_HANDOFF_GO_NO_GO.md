## 2. Twilio technical plan without a hidden live-SMS cost requirement

**Conservative written-course interpretation:** "at the very least Twilio" is not equivalent to "any fake SMS-shaped server". A real Twilio **Messages REST API transport** belongs in the final executable application (under a disabled-until-configured mode), while the supplied **FakeTwilio** remains independently useful for repeatable scheduling/Retrofit/Gson course evidence. The provider-specific communication's **actual execution status** must be shown separately.

**VERIFIED EXTERNAL TECHNICAL FACT (official sources, consulted Nov16 2026; these are NOT extra course instructions):**
- [Twilio test credentials](https://www.twilio.com/docs/iam/test-credentials) document `POST /2010-04-01/Accounts/{TestAccountSid}/Messages` with test `From` magic value `+15005550006` and no real SMS/charge. Test credentials do not prove carrier delivery, do not trigger status callbacks and may not be available to every account; they cannot use MessagingServiceSid.
- [Twilio Virtual Phone](https://www.twilio.com/docs/messaging/guides/guide-to-using-the-twilio-virtual-phone) is a distinct Console testing surface and, if an authorized account supports it, can show a provider API message in a virtual-device UI. It is not the supplied local FakeTwilio application.
- [Current trial guide](https://www.twilio.com/docs/usage/tutorials/how-to-use-your-free-trial-account) says new free trials end after 30 days, restrict recipients, geography, and **custom message content**. Do not promise free personalized due-date SMS using the trial.

**DESIGN RECOMMENDATION / future executable checks:**
1. `INT43-01` source/compiled: `TwilioRestTransport` is a real Retrofit/Gson client bound to an explicit official Twilio Messages API form POST, Basic auth injected only through secret configuration, proper `From/To/Body` (or a separately verified supported MessagingServiceSid mode), safe parsing of SID/errors, bounded timeout, no unapproved default sends. Run against a local protocol test server (not identical to FakeTwilio) and negative auth/error tests.
2. `INT43-02` O14 FakeTwilio remains actual separate loopback HTTP with original course protocol and a durable `SIMULATED` result; cron/scheduler triggers exactly once/unknown outcome without duplicating sends.
3. `INT43-03` optional explicit external proof: if eligible permitted existing Twilio account has test credentials or Virtual Phone, execute a real official provider API *non-delivery test only* with consent/account guard and redacted logs; record source SHA, exact API call/status, `TEST_ACCEPTED` not delivery. If unavailable, mark `PROVIDER_TEST_BLOCKED`, never mark provider proof PASS.
4. `INT43-04` regular actual phone dispatch is **not authorized** by the planning prompt; cannot send real SMS, spend money or use real student contacts. In-app due lists and disabled mode work regardless of provider/account status. Check privacy/opt-in separately before real users.

The written sources do not explicitly demand a *carrier-delivered* SMS, a paid Twilio account, a campus domain, real contact data or a permanently free cloud. Do not invent those obligations. They **do** mention Twilio and Retrofit; keep this provider adapter substantive, not a mislabeled simulator.
